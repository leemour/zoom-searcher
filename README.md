# zoom-searcher

`ztx` — консольный инструмент. Скачивает расшифровки встреч Zoom на диск и ищет по ним
с учётом морфологии русского языка.

Zoom умеет расшифровывать встречу, даже если видео не записывалось. Такие расшифровки лежат
в личном кабинете, во вкладке «Recordings & Transcripts → Transcripts». `ztx` забирает их
в текстовые файлы и дальше ищет локально, без сети.

## Почему через браузер, а не через API

Официального эндпоинта Zoom для транскриптов встреч **без облачной записи** не существует.
Это позиция форума разработчиков Zoom, а не проверенный нами факт. Через API доступны только
расшифровки записанных встреч и короткие AI-саммари.

Поэтому `ztx` работает через ваш собственный браузер. Он поднимает отдельное окно Chrome
с включённым портом отладки, вы входите в Zoom руками, а дальше инструмент забирает список
и файлы теми же запросами, которые делает сама страница. Пароль инструмент не вводит
и войти за вас не пытается.

Подробности устройства — в [docs/HOW_IT_WORKS.md](docs/HOW_IT_WORKS.md).

## Установка

Нужен [uv](https://docs.astral.sh/uv/).

```bash
uv tool install --from git+https://github.com/leemour/zoom-searcher ztx
```

Для разработки — из клона репозитория:

```bash
git clone https://github.com/leemour/zoom-searcher
cd zoom-searcher
uv sync
uv run ztx --help
```

Для `pull` нужен установленный Chrome или Chromium: инструмент ищет `google-chrome`,
`google-chrome-stable` и `chromium`. Playwright используется только при скачивании и
подгружается только в `pull` — поиск работает без браузера.

## Быстрый старт

```bash
ztx pull                       # откроется окно Chrome — войдите в Zoom вручную
ztx search устав капитал       # оба слова в одной реплике
```

## Команды

```
ztx pull [--cdp URL] [--limit N] [--dir ПУТЬ] [--no-launch]

ztx search СЛОВА... [--any] [--near N] [--exact] [--with ИМЯ]... [--speaker ИМЯ]
                    [--from YYYY-MM-DD] [--to YYYY-MM-DD] [--context N]
                    [--limit N] [--json] [--dir ПУТЬ]
```

### pull

Скачивает всё, чего ещё нет на диске. Уже скачанное пропускает, поэтому команду можно гонять
сколько угодно раз: повторный запуск после обрыва дотягивает остаток.

| Ключ | Что делает |
| --- | --- |
| `--cdp URL` | Адрес порта отладки Chrome. По умолчанию `http://127.0.0.1:9223` |
| `--limit N` | Обработать не больше N встреч из списка |
| `--no-launch` | Не запускать Chrome, подключиться к уже открытому |
| `--dir ПУТЬ` | Каталог с данными |

Если порт отладки не отвечает, `pull` сам поднимает окно Chrome и открывает в нём страницу
транскриптов — войдите в аккаунт и запустите команду снова. С `--no-launch` он вместо этого
завершится с ошибкой.

В конце печатается отчёт: сколько встреч в списке, сколько скачано, сколько пропущено. Встречи,
которые забрать не удалось, перечисляются по одной с причиной; в этом случае команда
завершается с кодом 1.

### search

По умолчанию требует, чтобы **все** слова запроса были в одной реплике.

| Ключ | Что делает |
| --- | --- |
| `--any` | Достаточно любого одного слова из запроса |
| `--near N` | Слова могут быть раскиданы по N соседним репликам |
| `--exact` | Строгое совпадение корня, без поправки на кривое распознавание |
| `--with ИМЯ` | Только встречи с этим участником. Можно повторять — нужны все перечисленные |
| `--speaker ИМЯ` | Только реплики этого говорящего |
| `--from`, `--to` | Границы по дате встречи, `YYYY-MM-DD`, включительно |
| `--context N` | Показать N реплик вокруг найденной с обеих сторон |
| `--limit N` | Сколько совпадений показать. По умолчанию 20 |
| `--json` | Выдать результат в JSON |
| `--dir ПУТЬ` | Каталог с данными |

Находки идут от свежих встреч к старым.

## Как ищет

**По корням слов.** Морфология — стеммер snowball: русский для кириллицы, английский для
латиницы, так что «деплой» и «deploy» обрабатываются каждое по своим правилам. Запрос «устав»
находит «уставный» и «уставного». Слова короче трёх символов не учитываются.

**Совпадение по умолчанию нестрогое.** Корни засчитываются, если один начинается с другого —
в любую сторону. Так «капитал» находит исковерканное распознаванием «капиталда», а обрезанное
«капит» находится по запросу «капитал». Послабление работает только для корней от четырёх
символов, чтобы короткие слова не тащили за собой пол-словаря.

Это нужно потому, что распознавание русской речи у Zoom плохое: слова обрываются и срастаются
с соседними. Ключ `--exact` отключает послабление и требует точного совпадения корня — он для
случая, когда мусора в выдаче больше, чем пользы.

**`--near N` — режим для машины, а не для глаз.** Он разрешает словам запроса лежать
в соседних репликах, и точность при этом падает: по запросу про счета он найдёт и «за счёт
сотрудничества». Этот режим сделан, чтобы отдать выборку языковой модели на разбор,
а не читать её самому.

**`--with` разбирается с именами участников.** Zoom подписывает участника именем устройства,
с которого тот зашёл, поэтому у одного человека бывает несколько подписей. Синонимы кладутся
в `aliases.json` в каталоге данных. В репозитории есть
[aliases.example.json](aliases.example.json) — скопируйте и правьте под себя. Фильтр смотрит
и на список говорящих в шапке файла, и на имя файла: название встречи нередко содержит имя
собеседника, а список говорящих пуст, если человек присутствовал молча.

`--speaker` — про другое: он оставляет только те реплики, которые произнёс этот человек.

```bash
ztx search бюджет найм --any
ztx search счет оплата --near 1
ztx search договор --exact
ztx search релиз --with Иван --from 2026-01-01 --to 2026-03-31
ztx search сроки --context 2
```

### Машинный вывод

`--json` печатает список находок. Поля — из `Hit.as_dict()` в `src/zoom_searcher/models.py`:

| Поле | Значение |
| --- | --- |
| `date` | Дата встречи, `YYYY-MM-DD` |
| `when` | Дата и время встречи в том виде, в каком их отдал Zoom |
| `meeting` | Название встречи |
| `file` | Имя файла с расшифровкой |
| `at` | Метка времени реплики от начала встречи |
| `speaker` | Кто говорит |
| `text` | Полный текст реплики |
| `matched` | Корни запроса, которые совпали |
| `context` | Соседние реплики, если просили `--context`, иначе пусто |

Это формат для передачи агенту или языковой модели.

## Где лежат данные

По умолчанию `~/.local/share/zoom-searcher`. Каталог переопределяется переменной окружения
`ZOOM_SEARCHER_DIR` или ключом `--dir`; ключ важнее переменной.

```
~/.local/share/zoom-searcher/
├── 2026-03-04_1030_planerka-po-relizu.txt   готовые расшифровки, по ним идёт поиск
├── raw/                                     исходные .vtt, как их отдал Zoom
├── .state/                                  служебное: кэш токена, профиль Chrome
├── index.tsv                                оглавление скачанного
└── aliases.json                             ваши синонимы имён (создаёте сами)
```

Имя файла — дата, время начала и название встречи: `YYYY-MM-DD_HHMM_название.txt`. Дату поиск
берёт прямо из имени файла, поэтому файлы переименовывать не стоит.

Внутри — шапка встречи, черта, дальше реплики. Реплики разделены пустой строкой и могут
занимать несколько строк:

```
Встреча: Планёрка по релизу
Дата: Mar 4, 2026 10:30 AM
Zoom ID: 00000000000
Говорят: Иван Петров, Мария Сидорова
Реплик: 2

————————————————————————————————————————————————————————————

[00:03:12] Иван Петров: Выкатываем в четверг, если тесты зелёные.

[00:03:40] Мария Сидорова: Тогда я предупрежу поддержку заранее.
```

`index.tsv` — оглавление с колонками `date`, `when`, `topic`, `file`, `bytes`. Оно
перестраивается в конце каждого `pull`.

Пути собраны в `src/zoom_searcher/config.py`.

**Данные никогда не хранятся в репозитории.** `.gitignore` отсекает `*.txt`, `*.vtt`, `data/`,
`.state/` и `aliases.json`.

## Приватность

Расшифровки чужих встреч — это персональные данные, а часто ещё и коммерческая тайна.

Инструмент держит их вне репозитория, `.gitignore` защищает от случайного коммита, в pre-commit
стоит `gitleaks`. Но это защита от одной конкретной ошибки, а не от всех. Куда вы денете
скачанное дальше — в чат с языковой моделью, в общую папку, в тикет — отвечаете вы.

## Чего инструмент не делает

- **Не чинит распознавание.** Качество распознавания русской речи у Zoom низкое. Пустой
  результат поиска **не доказывает**, что тему не обсуждали.
- **Не достаёт то, чего Zoom не отдаёт.** Часть записей помечена как недоступные для
  скачивания, часть отваливается с ошибкой. Такие встречи попадают в отчёт `pull`
  с причиной, но вернуть их нечем.
- **Не отличает пустую встречу от ненайденной темы.** Если распознавать было нечего, файл
  состоит из одной шапки. В поиске это выглядит так же, как «не обсуждали».
- **Не ищет по смыслу.** Семантического поиска нет и не планируется. Инструмент делает
  детерминированную выборку; осмысление — задача того, кому вы отдадите результат.
- **Не проверен на корпоративных аккаунтах.** Работа проверялась на личном аккаунте Zoom.
  На корпоративных, с другими настройками записи и доступа, не проверялась.

## Разработка

```bash
uv sync
uv run pytest
uv run ruff check .
uv run mypy src/
uv run pre-commit install
```

Есть [Taskfile](Taskfile.yml) для [Task](https://taskfile.dev/): `task --list` покажет всё,
`task check` прогонит линтер, типы, тесты и поиск секретов.

CI на GitHub Actions гоняет gitleaks, ruff, mypy и тесты на Python 3.11 и 3.13.

Как заводить окружение и что проверить перед пул-реквестом — в
[docs/CONTRIBUTING.md](docs/CONTRIBUTING.md).
